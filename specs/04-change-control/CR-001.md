# Change Request — CR-001

**ID:** CR-001
**Date:** 2026-08-24
**Status:** APPROVED (project owner decision)
**Requested By:** Project Owner

---

## Requested Change

Add `phone_number` field to the User entity and allow login using
either email address or phone number.

---

## Affected Requirements

| Requirement | Change |
|---|---|
| REQ-USR-004 — User Registration | Add `phone_number` as a required field |
| REQ-USR-005 — User Login | Accept phone number OR email as login identifier |

---

## Affected Plan Tasks

| Task | Change |
|---|---|
| TASK-AUTH-001 | Add `phone_number VARCHAR(15) NOT NULL UNIQUE` column to users migration |
| TASK-AUTH-002 | Registration endpoint accepts and validates phone number |
| TASK-AUTH-003 | Login endpoint accepts `identifier` (email or phone) instead of `email` |

---

## Affected Design

| Area | Change |
|---|---|
| Database | `users` table gains `phone_number` column |
| API | `POST /api/auth/login` request body changes `email` → `identifier` |
| Service | `AuthService.login()` queries by email OR phone number |

---

## Affected Tests

| Test | Change |
|---|---|
| TEST-AUTH-001 | Registration includes phone number |
| TEST-AUTH-003 | Login with email still works |
| TEST-AUTH-003b | Login with phone number works |
| TEST-AUTH-004 | Invalid phone format returns 400 |

---

## Impact Analysis

- **Additive only** — no existing functionality is removed.
- Phone number must be unique per user.
- Phone number format: numeric, 10 digits (Indian mobile), stored without country code prefix.
- Login `identifier` field accepts both email format and phone number format.
- Server resolves: `WHERE email = :identifier OR phone_number = :identifier`.
