## Requested Change

Add a gitignored `application-local.properties` file to the backend
`src/main/resources/` directory to support local development without
requiring system-level environment variables (`DB_URL`, `DB_USERNAME`,
`DB_PASSWORD`, `JWT_SECRET`).

---

## Problem Statement

`application.properties` reads all sensitive values from environment
variables (`${DB_URL}`, `${DB_USERNAME}`, `${DB_PASSWORD}`,
`${JWT_SECRET}`). In production and CI this is correct. However, during
local development a developer must set four system environment variables
before the app can start, which is inconvenient and error-prone.

Spring Boot's profile override mechanism allows a
`application-local.properties` file to override those placeholders when
the `local` profile is active — without touching the main config file and
without exposing credentials in version control.

---

## Proposed Solution

Create `src/main/resources/application-local.properties` containing
developer-facing overrides for local PostgreSQL credentials and a
dev-only JWT secret.

The file is already listed in `.gitignore` (`application-local.properties`)
so it can never be committed.

Activated by running:
```
mvnw spring-boot:run -Dspring-boot.run.profiles=local
```
or setting `SPRING_PROFILES_ACTIVE=local` in an IDE run configuration.

## File Content (proposed)

```properties
# application-local.properties — Local development overrides
# THIS FILE IS GITIGNORED — never commit it.
# Activate with: mvnw spring-boot:run -Dspring-boot.run.profiles=local

spring.datasource.url=jdbc:postgresql://localhost:5432/ebookstore
spring.datasource.username=postgres
spring.datasource.password=postgres

app.jwt.secret=ebookstore-local-dev-secret-key-not-for-production

spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```
