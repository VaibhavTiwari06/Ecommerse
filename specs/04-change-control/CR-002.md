## Technical Decision

### Search Vector Definition

```sql
search_vector tsvector GENERATED ALWAYS AS (
  setweight(to_tsvector('english', coalesce(title, '')),   'A') ||
  setweight(to_tsvector('english', coalesce(authors, '')), 'B') ||
  setweight(to_tsvector('simple',  coalesce(isbn, '')),    'D')
) STORED;
```

Publisher name and category name are resolved via JOIN at query time
and included in the search query via OR on their respective columns.

### GIN Index

```sql
CREATE INDEX books_search_idx ON books USING GIN(search_vector);
```

### Search Weight Priority

| Weight | Field | Rationale |
|---|---|---|
| A (highest) | Title | Primary search target |
| B | Authors | Second most relevant |
| C | Category / Publisher | Matched via JOIN |
| D (lowest) | ISBN | Exact match always works |

### Query Pattern

```sql
SELECT b.*, ts_rank(b.search_vector, query) AS rank
FROM books b
JOIN categories c ON b.category_id = c.id
JOIN publishers p ON b.publisher_id = p.id,
     to_tsquery('english', :searchTerm) query
WHERE b.search_vector @@ query
   OR c.name ILIKE :rawTerm
   OR p.name ILIKE :rawTerm
ORDER BY rank DESC;
```

---

## Impact Analysis

- **Performance:** GIN index gives sub-millisecond search on 113–10,000 books.
- **Relevance:** Results ranked by `ts_rank` — most relevant books first.
- **Stemming:** PostgreSQL English dictionary handles stemming automatically.
- **No extra services:** Stays within existing PostgreSQL — no Elasticsearch needed.
- **Migration:** One additional column + one index in `V6__books.sql`.
